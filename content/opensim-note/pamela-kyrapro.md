# Pamela 与 KyraPro 原子动作切分汇报稿

## 一、报告范围与总体流程

汇报内容：目前 Pamela 和 KyraPro 两套数据的原子动作切分方案、测试中发现的问题，以及现阶段的解决方案。

两套数据的整体思路都是：先利用视频中的倒计时把长视频切成单个 exercise segment，再基于 HMR 导出的三维人体动作轨迹，在每个 segment 内寻找完整、稳定、可重复验证的动作周期。

需要先区分两个概念：

- **视频切片**：根据倒计时，把一整段训练视频拆成若干个 exercise segment；
- **原子动作**：在每个 segment 内进一步找到一个完整、稳定、可重复验证的动作周期。

因此，一个 30 秒左右的 segment 不直接等于一个原子动作，而是原子动作检测的输入范围。

## 二、Pamela 原子动作切分逻辑

Pamela 的流程可以概括为：长视频倒计时切段 → HMR 三维动作提取 → 完整动作周期检测 → OCR 动作归类与去重。

### 2.1 基于倒计时的初始切段

首先读取 Pamela 视频右上角的倒计时区域，使用 PaddleOCR 识别倒计时数字，同时兼容 `mm:ss` 和纯秒数格式。

由于视频中存在 OCR 漏检、数字跳变、零值持续多帧以及倒计时重新开始等情况，所以没有采用“识别到单帧 0 就立即切段”的方式，而是使用状态机确认边界。

当前的判断原则是：

- 倒计时必须先出现稳定的下降序列；
- 出现 0 后，需要检测到下一轮倒计时重新开始；
- 连续多个 0 只保留最后一个 0 作为边界；
- 单独一次错误的 0 不算边界；
- 中间漏检不能自动制造零值；
- 结尾没有明确重新开始的尾部不作为新的有效动作片段；
- 持续时间太短的片段直接丢弃。


### 2.2 使用 HMR 三维动作轨迹

每个有效切片都有对应的 HMR 动作结果，最终使用带骨骼动画的 `world4d.glb` 进行周期分析。

动作特征主要包括：

- 骨盆、躯干、手、脚和四肢等命名关节；
- 关节相对于骨盆的相对位置；
- 关节旋转；
- 关节速度；
- 左右关节交换后的镜像姿态。

### 2.3 完整动作周期检测

Pamela 的原子动作不是按照固定时长截取，也不是直接选取一段最相似的局部片段，而是寻找完整的动作编排周期。

检测过程主要包括以下几步（下面详细解释每一步的目的和判断依据）：

1. 在整段动作轨迹上寻找重复间隔；
2. 检查周期内部的动作阶段是否按照相同顺序出现；
3. 检查每个阶段是否能够完整返回，周期边界是否稳定；
4. 检查每轮动作的持续时间和可观察动作次数；
5. 使用全身受限 DTW 比较不同周期之间的姿态和速度变化；
6. 从多个完整周期中选取最具有代表性的一轮作为 canonical representative。

代表周期不是默认取第一轮，而是计算每一轮与其他完整周期的平均 DTW 距离，选择最接近整体中位状态的真实周期。这样可以避开第一轮准备动作、中间不完整动作、擦汗或调整姿态等异常轮次。

这里的“平均 DTW 距离”可以理解为“这一轮动作和其他所有完整轮次的平均差异”。假设一个 segment 中通过完整性检查后有 4 轮动作，分别记为 A、B、C、D，那么 A 的平均 DTW 距离为：

```text
mean_DTW(A) = [DTW(A,B) + DTW(A,C) + DTW(A,D)] / 3
```

B、C、D 也分别进行同样的计算。平均值越小，说明这一轮和其他轮次越接近，越能代表这个 segment 中动作的共同形态。

DTW 是动态时间规整距离。它允许两轮动作存在合理的速度差异，例如一轮稍快、另一轮稍慢，同时比较整段动作中所有关节的姿态和速度变化。这里使用的是受限 DTW，时间匹配只能在有限范围内调整，不能把任意两个时间点无限制地对齐。因此，局部姿态相似但阶段顺序不同的片段，仍然会得到较大的整体距离。

最终选择的是实际出现在视频中的一轮完整动作，而不是把多轮动作平均成一个不存在的视频。该轮同时需要满足动作阶段完整、边界稳定、时间变化合理，并且平均 DTW 距离较小。


### 2.4 左右侧动作的处理

Pamela 的左右处理主要用于动作命名和镜像标注。动作周期本身先按照该 segment 中的完整重复结构确定；之后再根据 OCR 名称中明确出现的 `LEFT` 或 `RIGHT` 记录左右语义。

例如：

```text
SIDE LUNGE LEFT
SIDE LUNGE RIGHT
```

会归为同一个动作组，但保留两个独立的视频，分别标记为 `left_mirror` 和 `right_mirror`。左右视频不进行水平翻转，也不拼接。`SIDE TO SIDE`、交替左右等已经包含双侧语义的名称，则作为一个无镜像动作保留。

### 2.5 OCR 动作名称归类

运动轨迹负责回答“哪里是完整动作周期”，但不负责决定两个动作在语义上是否属于同一类。动作类别主要通过视频画面中的 exercise title 进行识别。
具体做法是：

- 在倒计时左侧截取动作名称区域；
- 在一个 segment 的多个时间点进行采样；
- 使用 PaddleOCR 识别动作名称；
- 做大写化、标点归一化和无关词清理；

归类规则是：

- 每个 segment 先视为一个动作语义单元；
- 相同 OCR 名称的 segment 可以归为同一动作；
- 同名动作中只保留质量最好的完整周期作为 canonical action；
- 其他周期保留在 `sources.json` 中作为来源证据；
- 姿态相似但 OCR 名称不同的动作不强行合并；

### 2.6 左右镜像标注

左右镜像不是根据画面坐标判断，而是根据 OCR 名称中明确出现的 `LEFT` 或 `RIGHT` 判断。
例如：

```text
SIDE LUNGE LEFT
SIDE LUNGE RIGHT
```

会归为同一个动作组，但保留两个独立的视频：一个标记为 `left_mirror`，另一个标记为 `right_mirror`。

左右动作不做水平翻转，也不拼接成一个视频。对于 `SIDE TO SIDE`、交替左右等本身已经包含双侧动作的名称，则标记为无镜像，不再拆分。

## 三、Pamela 测试中发现的问题及当前解决方案

Pamela 当前暴露出的主要问题首先来自输入视频和前置结果的完整性，可以归纳为三类视频问题。它们需要分别处理，不能全部归结为原子动作算法本身。

这三类问题都会直接影响后续的原子动作周期寻找：多人会使单人 HMR 的人体序列发生错位，shot change 会把不同镜头中的人体轨迹拼在一起，中央缩小预告则会使人体尺度和关键点轨迹突然改变。因此，质量控制必须发生在 HMR 重跑和周期分析之前。

### 3.1 三类问题总览

| 问题类型 | 典型现象 | 对 HMR 和周期分析的影响 | 处理原则 |
| --- | --- | --- | --- |
| 双人或多人 | 两个人都在中央；或 Pamela 在中央、另一人在左右两侧作为背景 | 单人 GVHMR 可能跟错人、序列跳到另一人物，导致骨架错位和周期不完整 | 用 ViTPose 识别每个人的 2D 关键点、置信度和人体框，再决定 GVHMR 或 PromptHMR 多人模式 |
| shot change | 镜头切换、画面突变、人物框和关键点轨迹同时跳变 | 一个视频段内混入两个镜头，HMR 轨迹不连续，周期边界失真 | 使用 PySceneDetect 产生场景候选，再用人体框和 2D 关键点变化确认；必要时先切开再分别运行 HMR |
| 中央画面边界虚化/缩小预告 | 先出现完整人物，随后虚化或缩小为中央小画面；通常持续约 10 秒，并预告后面约 30 秒的完整动作 | 小画面阶段的人体尺度、清晰度和关键点分布异常，容易生成错误 HMR 或错误周期 | 标记预告区间并排除该区间，使用后续正常画面重跑；不直接删除对应完整动作 |

### 3.2 基于 ViTPose 的多人识别和位置判断

错误的第一轮 HOG 代理标签不再使用。新的质量标签流程对视频均匀采样帧，逐帧保存以下信息：

- 每个人的人体框 `bbox` 及检测置信度；
- 17 个 COCO 2D 关键点及每个关键点的置信度；
- 有效关键点数量、平均关键点置信度；
- 人体框中心、面积和相邻采样帧的轨迹变化。

只有在关键点数量和置信度达到最低要求，并且在多个采样帧中持续出现的人体，才计入人数。根据人体框中心和面积进行位置分类：

```text
单个有效人体位于中央       → single_central_person → GVHMR
两个或更多有效人体位于中央  → central_multi_person → PromptHMR --keep-all-persons
最大人体位于中央、其他人在两侧 → side_background_person → GVHMR 主人物，必要时回退多人模式
关键点不足或严重遮挡        → pose_insufficient / pose_occlusion → 人工复核
```

`multi_person` 只在多人条件得到多个采样帧支持时添加，避免把单帧检测噪声当作第二个人。每个片段的原始关键点和人体框证据写入 JSONL，便于抽帧复核和选择最终人体序列。

### 3.3 shot change 检测

shot change 使用 Multi-THuMBS 中的 PySceneDetect 接口作为场景候选检测器，并联合 ViTPose 的人体时序特征进行确认。每个候选边界保留三类证据：

1. `scene`：PySceneDetect 的像素/场景变化分数；
2. `bbox`：边界前后人体框的面积、位置和 IoU 是否突然变化；
3. `pose`：归一化 2D 关键点轨迹和可见关键点数量是否突然变化。

只有场景证据与人体证据相互支持，或者场景边界本身非常明确时，才标记为 `shot_change_candidate`。确认后的处理顺序为：

```text
检测边界 → 保存边界帧和触发来源 → 在边界处分割 → 对各子段分别运行 HMR
```

如果切分后仍然没有足够长、连续的人体轨迹，该片段标记为 `needs_review`，而不是将不同镜头强行拼接成一个动作周期。

### 3.4 中央画面边界虚化/缩小预告检测

这类问题不能只用单一的模糊度阈值判断。新的检测同时使用画面级和人体级时序证据：

- 画面级：Laplacian 方差、边缘密度、局部熵，以及中央区域和四周区域的清晰度变化；
- 人体级：最大人体框面积占比、人体框宽高、人体框中心、有效关键点数量和关键点置信度；
- 时序级：从正常大画面到过渡/虚化，再到中央稳定小画面的持续变化，并检查后续是否出现正常大小的完整人物。

只有以下模式同时出现时，才标记 `center_preview_candidate`：

```text
正常完整人物
    → 过渡或边界虚化
    → 人体框稳定缩小到中央、但关键点仍可见
    → 后续出现较长的正常完整动作
```

输出中记录 `preview_intervals`，包括开始时间、结束时间和触发证据。该区间只作为 HMR 的排除区间，不删除后续完整动作；后续正常画面仍需参与周期检测。如果只有整体失焦、人物暂时蹲下、短时遮挡或镜头拉远而没有稳定的小画面模式，则不标记为预告。

### 3.5 三类问题对应的 HMR 策略

| 标签/判断结果 | HMR 策略 | 后续动作周期处理 |
| --- | --- | --- |
| `single_central_person` | GVHMR | 正常进入完整周期检测 |
| `central_multi_person` | PromptHMR 多人模式，保留全部人体序列 | 比较各人体序列的完整周期、稳定性和质量，选择最终序列 |
| `side_background_person` | 先用 GVHMR 提取中央主人物 | 若主人物轨迹不稳定，再运行多人模式复核 |
| `shot_change_candidate` | 先按确认边界切分，再分别运行 HMR | 不跨镜头寻找周期 |
| `center_preview_candidate` | 排除预告区间，使用后续正常画面重跑 | 只从正常完整动作中寻找周期 |
| `pose_insufficient` / `pose_occlusion` | 暂不自动接受结果 | 进入人工复核或重新抽帧 |

当前新的打标实现为 `scripts/quality_tag_vitpose.py`，输出目录为 `AAProblems问题视频/vitpose_parts`。标签阶段完成后，才根据标签选择 GVHMR 或 PromptHMR，并将 HMR 结果和标签结果分开保存，避免把质量控制文件混入原始视频目录。



## 四、KyraPro 原子动作切分逻辑

KyraPro 的总体思路和 Pamela 一致，仍然是：先通过倒计时得到 exercise segment，再通过三维人体轨迹提取完整动作周期。

但 KyraPro 在倒计时识别和跨 segment 动作归并方面采用了更专门化的处理。

### 4.1 KyraPro 的倒计时识别

KyraPro 的倒计时具有比较明显的视觉特征，包括右上角倒计时、斜体数字、紫色或粉色数字，以及结束阶段的红色数字。尤其是单独的斜体数字 0，容易被通用 OCR 漏掉。
采用的自适应采样，分为三个状态：

- 空白搜索阶段：低频采样，大约 1 FPS；
- 正常倒计时阶段：按照设定频率跟踪；
- 接近 0 或出现重置跳变时：提高到视频原始帧率逐帧检查。

KyraPro 还增加了以下规则：

- 短暂 OCR 漏检时，只允许暂时保持最近的正数；
- 只有真实 0 连续出现，并且后续出现新一轮正数倒计时，才确认边界；
- 结尾的真实 0 可以作为终止边界；
- 长时间空白后出现的新倒计时不会错误继承上一轮的零值；
- 错误的单帧 0、旧零值和倒计时动画中的中间数字会被过滤。


### 4.2 KyraPro 的动作周期检测

切片完成后，KyraPro 使用和 Pamela 相同的核心动作检测器：

- 基于骨骼关节位置、旋转和速度；
- 先查找周期性重复；
- 再进行阶段顺序和周期完整性检查；
- 使用受限 DTW 比较不同轮次；
- 选择最稳定、最具代表性的真实周期；
- 对左右动作保留完整的实际编排；
- 没有充分周期证据的区间保留为未分配区间。

KyraPro 对左右动作的完整编排处理更严格。很多 KyraPro 动作不是单个左右交替，而是“左侧重复若干次，再右侧重复若干次”。同一侧的重复只能作为子周期证据，不能直接把单侧子周期当成完整原子动作。

如果真实结构是左侧动作组加右侧动作组，算法会：

- 先分别识别两个相邻的单侧重复块；
- 检查两个块的动作阶段和重复次数；
- 使用左右关节交换后的镜像轨迹进行匹配；
- 用整体受限 DTW 确认两个块属于同一个动作；
- 保留两侧实际观测到的全部重复次数。

因此，KyraPro 不会把一个左侧子周期错误缩短成原子动作，也不会预设固定的 `1+1`、`2+2` 或 `5+5` 次数。

对于只观察到一次完整左右组合的情况，系统会保留候选并标记需要复核，不把“一次观察到的组合”直接当作已经重复验证的周期。

### 4.3 KyraPro 的跨 segment 动作归并

KyraPro 当前不依赖 Pamela 那样的动作名称 OCR 做主要语义归类，而是对所有 segment 中检测到的完整动作候选做跨 segment 的运动聚类。

具体过程是：

1. 为每个完整动作候选提取姿态和速度描述；
2. 计算任意两个动作候选之间的全身 DTW 距离；
3. 只有当候选与动作簇中的所有成员都满足距离阈值时，才允许合并；
4. 同时限制动作持续时间比例，避免将时长差异过大的动作合并；
5. 每个聚类最终只保留一个 canonical representative；
6. 其他重复候选移动到 `duplicate_evidence` 中，作为审计证据保存。

当前 KyraPro v8 的关键参数是：

- 全身动作距离阈值：0.8；
- 最大持续时间比例：1.35；
- 不启用镜像等价，也就是说左右镜像默认不会自动被视为同一个动作；
- 代表动作优先考虑周期阶段一致性、时间稳定性和 DTW medoid 质量。

因此，Pamela 和 KyraPro 的主要区别是：

- Pamela：先用 OCR 动作名称决定语义类别，再在同名动作中选择代表周期；
- KyraPro：主要依靠完整动作周期的全身运动描述进行跨 segment 聚类。

### 4.4 KyraPro 测试中发现的问题及当前解决方案

KyraPro 的主要风险不是倒计时切段本身，而是左右动作编排在周期检测时容易被局部重复“吸走”。例如，真实动作结构是左侧连续若干次、再右侧连续若干次，单侧重复往往比完整的左右组合更容易被检测器匹配。如果直接把局部重复当成原子动作，会产生以下结果：

- 左右动作块被截短，只保留其中一侧；
- 原本完整的 `AAB` 组合被缩短成局部 `A`；
- 左侧和右侧被错误地拆成两个互不相关的动作；
- 周期边界落在半个动作上，首尾不能回到相同阶段；
- 实际次数被改写成预设的 `1+1`、`2+2` 或 `5+5`，与视频中的真实编排不一致。

当前的处理方式是把“单侧重复”降级为子周期证据，而不是直接输出原子动作。具体步骤如下：

1. 先在整段轨迹上寻找全局重复支持，确定候选动作块的起止范围；
2. 检查候选内部的阶段顺序，确认左侧动作组和右侧动作组都能完整出现；
3. 检查每个动作组的首尾是否回到相同阶段，排除落在半个动作上的边界；
4. 对左右动作块交换关节标签后，计算镜像轨迹的一致性；
5. 使用覆盖完整左右组合的整体受限 DTW，而不是只比较某个单侧局部片段；
6. 保留视频中实际观察到的左右顺序、重复次数和持续时间，不强行补齐或重写次数；
7. 只有在完整双侧组合得到足够证据时才输出 canonical 动作，否则保留候选并标记为 `needs_review` 或 `no_complete_cycle`。

这样处理后，局部单侧重复仍然可以帮助定位动作阶段，但不会越过完整性检查直接成为最终原子动作。对于确实只有一个完整左右组合、没有第二轮可用于交叉验证的 segment，也不把它伪装成“已稳定验证”的周期，而是进入人工抽检队列。


## 五、下一步计划

下一步按照“先完成 Pamela 合集验证，再处理 KyraPro”的顺序推进，不在两套数据之间交叉修改，避免问题来源和修复效果难以判断。



### 5.1 再处理 KyraPro 原子动作切分

Pamela 合集验收完成后，开始处理 KyraPro，顺序固定为：

1. 使用 KyraPro 专用倒计时规则重新确认 exercise segment；
2. 验证每个 segment 的起止边界、视频时长和 HMR 输入是否对应；
3. 在 segment 内检测完整动作周期，检查阶段顺序、边界稳定性和可观察动作次数；
4. 单独检查左右动作组，把单侧重复作为子周期证据，不把它直接当成完整原子动作；
5. 对 `AAB` 等多阶段组合结构进行完整性检查，防止被缩短成局部 `A`；
6. 使用镜像匹配和整体受限 DTW 确认左右动作组属于同一完整编排；
7. 在跨 segment 的全身 DTW 聚类中整理 canonical 动作和 `duplicate_evidence`；
8. 人工抽检代表周期、动作边界、左右重复次数、未分配区间以及 `needs_review` 结果。

KyraPro 阶段还会单独统计：完整双侧组合、只有单侧子周期、只有一次完整组合、`no_complete_cycle` 和程序异常，避免把不同性质的结果混为一谈。

## 六、总结

最后总结一下：

Pamela 目前采用“倒计时切段 + HMR 周期检测 + OCR 语义归类 + 左右镜像标注”的方案，重点保证动作名称和左右语义的可解释性。KyraPro 则采用“专用倒计时识别 + HMR 周期检测 + 全身 DTW 跨 segment 聚类”的方案，重点保证动作周期和跨片段去重的稳定性。两套方案的底层周期检测已经统一，主要差异在于动作语义归类方式和倒计时切分器的专门化程度。
