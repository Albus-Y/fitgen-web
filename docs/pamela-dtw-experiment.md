# Pamela 扰动实验：服务器 Anchor xTW

页面为 `dist/pamela-dtw-demo/index.html`，由模块 4 的第三个 demo 入口进入，也可从音乐/动作 beat 审查页的第二个选项卡进入。三栏与共用原声、音乐八拍、原始 beat 均继续保留，播放速度固定为 1×。

原版（标准、全局、无约束）DTW 已提交到 `experiment/pamela-vanilla-dtw-20261126`，提交 `8c27a9c`。该分支保留当时的实现、说明与失败结果。当前 main 使用服务器现有模块，没有在浏览器重新实现该求解器。

## 实际调用与版本

服务器项目为 `Module2_xtw`，包版本 0.4.2，Git HEAD 为 `65d3b9b11d18357d26da07a3ee681669d553c91c`。服务器已有未提交修改，因此以结果清单中的源码文件 SHA256 为实际版本依据，不只依赖 HEAD。

调用入口为 `xtw.retime_motion_to_music`，执行默认 Anchor 路线：

1. 事件时间归一化值与前后间隔的对数构成三维 descriptor，代价为加权 L1。
2. 双侧 Drop-DTW 允许丢弃事件，生成严格单调的一对一锚点。
3. GDTW 根据锚点参考映射、正则和速度硬约束生成音乐时间到扰动输入时间的映射。
4. 使用服务器现有重采样函数得到 20 FPS 关节位置。

使用模块默认参数，没有根据恢复真值调参：

| 参数 | 值 |
|---|---|
| descriptor 三项权重 | 1、1、1 |
| interval epsilon | $10^{-8}$ |
| 两侧 drop cost | 各为代价矩阵第 75 百分位的一半；实际值逐案例保存 |
| GDTW 采样点 | 181 |
| candidate_count | None，沿用后端默认 |
| 累计 / 瞬时速度正则 | 0.02 / 0.10 |
| 迭代 / 细化比例 | 4 / 0.15 |
| 真实秒速度范围 | 0.5–2.0 |
| 后端 | 官方 GDTW C++，固定版本 `1adb1d5` |

`results/manifest.json` 记录参数、包版本、实际源码和已加载后端的 SHA256、Python/NumPy/SciPy 版本、生成脚本指纹和输入清单指纹。各片段结果文件也有 SHA256。`.gitattributes` 保持这些 JSON 的 LF 换行，以免 Windows checkout 改变字节校验和。

## 输入、时间轴与信息边界

三个片段均为已审查 SMPL-X GLB 身体 22 关节世界坐标，600 帧 / 20 FPS / 30 秒；不是完整 SMPL-X 旋转参数或网格。原数据与音乐分析不变，新增结果不包含重复视频。

扰动与原版分支完全相同。固定种子 20261126 产生两个相位，速度函数为：

$$
\phi'(t)=1+a[0.65\sin(2\pi t/T+p_1)+0.35\sin(4\pi t/T+p_2)].
$$

无、轻微、中等、明显扰动分别取 $a=0,0.2,0.4,0.65$。$\phi(0)=0$、$\phi(T)=T$，速度严格为正；$\phi(t)$ 表示扰动时间读取的原动作时间。

- `tracked` 为默认模式：已确认事件与动作一起受扰动，单独检查对齐模块。
- `redetect`：从扰动动作按审查版规则重新检测事件，供完整流程观察。
- 导出脚本仅向服务器提供扰动后的坐标、输入 beat、音乐 beat 和帧率/时长；不提供原始事件、原始动作坐标或真实扰动映射。种子与档位是实验标识，不进入 xTW 函数参数。
- 真实映射只在输入生成和求解后的评价中使用。所有输入位置的 SHA256 在页面 Web Worker 中再次验证；缺失结果或输入不符时会报错，不回退到原版 DTW。

审查版重检测采用 Gaussian sigma=5 帧、`reflect` 边界、0.2 秒最小间隔。服务器通用高层 `extract_motion_beats` 使用 `nearest`，某些扰动会多出首尾事件。因此本轮通过低层 xTW 接口传入审查版 beat，保持对齐模块之外的实验条件不变。独立 SciPy 检查也明确使用 `reflect`，不声称与高层提取器完全等价。

服务器动作时长按 $(T-1)/FPS$ 计算。600 帧的末帧位于 29.95 秒，媒体尾部保持至 30 秒；调用时额外重复末帧作为 30 秒边界姿态，输入变为 601 帧，内容与拍点不变。输出仍为 600 帧，末端保持策略与原版分支一致。

## 静态网页与封装

服务器计算 3 片段 × 4 档扰动 × 2 种输入，共 24 个案例；前端在这些已计算案例间切换，种子不可现场修改。更换种子需重新生成服务器结果。

- `scripts/export_pamela_xtw_inputs.mjs`：复用实验扰动函数，生成 12 个输入骨架和 24 个 beat 输入配置。
- `scripts/run_pamela_server_xtw.py`：直接导入服务器现有模块，保存紧凑发布结果与完整验证骨架；不安装依赖，不修改服务器算法。
- `dist/pamela-dtw-demo/dtw.js`：只做服务器结果和映射校验、插值，不含 DTW 求解实现。
- `experiment.js` / `worker.js`：重建输入、核对 SHA256、按服务器映射重采样、计算评价。
- `results/`：约 287 KiB，保存锚点、丢弃事件、参考映射、实际 GDTW 映射、诊断和版本信息。

网页三路骨架复用原始数据和线性插值；已逐点对照服务器实际输出。完整验证骨架仅存放在实验目录，不随 Pages 发布。

## 评价

映射事件贴拍误差继续使用全部输入事件，包括没有被 Drop-DTW 选作锚点的事件；不能通过丢弃难匹配事件缩小指标的分母。额外显示实际重检测数量与贴拍误差。

恢复误差比较原始时间 $t$ 与 $\phi(t)$ 或 $\phi(\gamma(t))$。原序列记为 0 不意味着它已完全踩拍。服务器约束的是 $\gamma'(t)$；表中的总速度还叠加输入扰动 $\phi'$，二者分别展示。

固定种子、中等扰动、`tracked` 的实际结果：

| 片段 | 扰动后贴拍中位数 | xTW 后贴拍中位数 | 扰动时序 RMSE | xTW 时序 RMSE | 锚点数 |
|---|---:|---:|---:|---:|---:|
| SLOW SQUAT | 127.65 ms | 147.13 ms | 1250.59 ms | 1272.43 ms | 18 |
| JUMPING JACK | 146.20 ms | 55.12 ms | 1250.59 ms | 1293.46 ms | 30 |
| REACH DOWN JUMP | 124.00 ms | 126.26 ms | 1250.59 ms | 1267.76 ms | 35 |

本版消除了原版 DTW 的极端局部变速，但这三组默认设置没有恢复原始时序。JUMPING JACK 的映射事件更贴音乐，另两组没有改善。以上结果不作为算法有效性的自动通过依据；默认参数的 GDTW 输出接近恒等映射，效果仍需进一步讨论。

## 复现与验证

```text
node scripts/export_pamela_xtw_inputs.mjs <新的输入目录>
```

将输入目录与 `run_pamela_server_xtw.py` 放到服务器独立实验目录，用已有环境执行：

```text
python run_pamela_server_xtw.py --module-root <Module2_xtw目录> --inputs <输入目录> --output <新的结果目录>
```

将 `publish/` 内的四个 JSON 放入 `dist/pamela-dtw-demo/results/`；`validation/` 保留为独立参考数据。新增服务器结果或源码后，更新前端资源 URL 的版本串，避免浏览器复用旧模块。

```text
node scripts/test_pamela_dtw.mjs <本地验证输出目录> <服务器validation目录>
python scripts/build.py
python scripts/check.py
```

验证覆盖 24 组输入 SHA256、结果 SHA256、丢弃计数、锚点单调性、GDTW 端点与速度、输出形状、重检测事件、无扰动恒等输入、错误配置拒绝、旧音频接口一致性。带独立服务器骨架时共 445 项检查；24 组重采样的最大绝对坐标差为 $2.3842\times10^{-7}$，在 float32 数值误差范围内。
